# Meters, Invoices & Payments Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** จดมิเตอร์ ออกใบแจ้งหนี้รายเดือน ตรวจสลิป ออกใบเสร็จ (นิติบุคคล) และดูใบแจ้งหนี้ ชำระ ส่งสลิป รับแจ้งเตือน ดูใบเสร็จ (ผู้เช่า) — FR11–17 ด้วยข้อมูลจำลองใน localStorage

**Architecture:** กฎคำนวณเป็นฟังก์ชันล้วน (`src/billing/rules.ts`, `periods.ts`) → `localBillingApi` (ก้อนเดียว `condo:billing` อ่านจาก storage ใหม่ทุกครั้ง อ้างอิง `condo:property` ผ่าน `PropertyApi`) หลัง interface `BillingApi` → `BillingProvider`/`useBilling()` (อยู่ใน `AppShell` เพราะกระดิ่งแจ้งเตือนอยู่ใน header) → หน้านิติบุคคล 4 แท็บ + หน้าผู้เช่า + กระดิ่ง

**Tech Stack:** เดิม (React 19, Vite, TS, Tailwind v4, react-router, react-i18next, Vitest + RTL + user-event) ไม่เพิ่มแพ็กเกจ

## Global Constraints

- ไม่มีหลังบ้าน ไม่เพิ่มแพ็กเกจ ห้ามเรียกเครือข่าย; หน้านิติบุคคลเข้าได้เฉพาะ `juristic`, หน้าผู้เช่าเฉพาะ `tenant` (guard เดิมของ prefix)
- localStorage คีย์ `condo:billing` = `{ version: 1, rates, readings, invoices, notifications }`; ข้อมูลว่าง/เสีย/รูปผิด/ผิดกฎ/อ้างอิงห้อง-สัญญาที่ไม่มีใน `condo:property` → seed ใหม่ทั้งก้อน ไม่ throw; storage อ่าน/เขียนไม่ได้ต้องทำงานในหน่วยความจำ; ความล้มเหลวชั่วคราวห้ามถูกแคช; **อ่านจาก storage ใหม่ทุกครั้งก่อนตรวจและแก้** (ห้ามถือสำเนาในหน่วยความจำข้ามการเรียก ยกเว้นเป็น fallback เมื่อ storage ใช้ไม่ได้); จากอ่านถึงเขียนไม่มี `await` คั่น
- รอบบิล = `YYYY-MM`; "วันนี้" ฉีดได้ (`today: () => string`); คำนวณวันที่ด้วย UTC บนสตริง `YYYY-MM-DD` (ใช้ `src/property/dates.ts`)
- อัตรา: น้ำ ฿/หน่วย, ไฟ ฿/หน่วย, ส่วนกลาง ฿/ตร.ม. จำนวนเต็ม > 0 (ตั้งต้น 18 / 7 / 60); ใบแจ้งหนี้เก็บอัตราที่ใช้ตอนออก (snapshot)
- มิเตอร์: จำนวนเต็ม ≥ 0, `Curr ≥ Prev`, หนึ่งรายการต่อห้องต่อรอบ; `Prev` มาจาก `Curr` ของรอบก่อนหน้าของห้องนั้น (แก้เองไม่ได้) และกรอกเองได้เฉพาะเมื่อห้องนั้นไม่เคยมีรอบก่อน; **แก้ได้เฉพาะรายการล่าสุดของห้องและยังไม่ออกบิลของรอบนั้น**
- ห้องที่ถูกเรียกเก็บในรอบ: มีสัญญาที่ช่วงทับซ้อนเดือนนั้น และไม่ถูกยกเลิก (หรือยกเลิกแต่ `cancelledAt` ≥ วันแรกของรอบ); ห้องหนึ่งมีบิลเดียวต่อรอบ ถ้ามีสองสัญญาทับเดือนเดียวกันให้ใช้สัญญาที่เริ่มทีหลัง
- เงิน: ทุกบรรทัดปัดเป็นบาทเต็ม (ปัดครึ่งขึ้น) แล้วรวมเป็นยอดสุทธิ; ค่าส่วนกลาง = ขนาดห้อง × อัตรา คิดเต็มเดือน
- ใบแจ้งหนี้: `number` = `INV-<YYYYMM>-<รหัสห้องไม่มีขีด>` ไม่ซ้ำ, `dueDate` = วันที่ 5 ของเดือนถัดไป, เก็บ snapshot `unitCode`, `tenantName`, `tenantPhone`, ไม่มีการแก้/ยกเลิกหลังออก; ออกบิลทั้งรอบ: ข้ามห้องที่ไม่มีมิเตอร์และห้องที่มีบิลแล้ว กดซ้ำไม่สร้างซ้ำ
- สถานะที่แสดง (คำนวณ): paid (มีสลิปอนุมัติ) > verifying (มีสลิปรอตรวจ) > overdue (ยังไม่ชำระและ `dueDate` < วันนี้) > unpaid; paid แต่ไม่มี `receipt` = "รอออกใบเสร็จ"
- สลิป: JPG/PNG (ชนิดและนามสกุล) ≤ 5 MB (5 × 1024 × 1024 ไบต์ เท่ากับพอดีผ่าน) เก็บเฉพาะชื่อ/ขนาด/ชนิดไฟล์; ส่งได้เมื่อบิลยังไม่ paid และไม่มีสลิปรอตรวจ; ตรวจแล้วเปลี่ยนไม่ได้; ปฏิเสธต้องมีเหตุผล; ใบเสร็จออกได้เมื่อ paid และครั้งเดียว; ข้อความผิดพลาดสลิป "กรุณาแนบไฟล์สลิปการโอนเงินให้ถูกต้อง"
- แจ้งเตือน: ผูกกับ `recipientPhone` (snapshot ของบิล) ชนิด invoiceIssued / slipRejected / receiptIssued; ผู้เช่าเห็นเฉพาะของเบอร์ตัวเอง
- ผู้เช่าเห็นเฉพาะบิลที่ `tenantPhone` ตรงกับเบอร์ในบัญชี; บัญชีทดลอง `tenant01` ใช้เบอร์ `0810000001` (ตรงกับผู้เช่าห้อง A-1204 ในข้อมูลตัวอย่าง) ส่วน `staff01`/`tech01` ยังเป็น `0800000000`
- ข้อความ UI ทั้งหมดผ่าน i18n ครบ th และ en (เทสเทียบคีย์เดิมจะ fail ถ้าขาด); เงิน `฿1,234` ชิดขวา `tabular-nums`; วันที่ พ.ศ./ค.ศ. ตามภาษา (`formatDate`, `formatBaht` เดิม)
- ฟอร์มใน `Modal` + `FormField`; กดส่งซ้ำระหว่างรอไม่ได้ (ปุ่ม disabled + ref กัน); ผิดแล้วโฟกัสช่องแรกที่ผิด; อนุมัติ/ปฏิเสธ/ออกบิลทั้งรอบต้องยืนยัน; ตารางเลื่อนข้างในกรอบของตัวเอง; Modal เลื่อนได้บนจอเตี้ย
- ข้อผิดพลาดชั้นข้อมูล: `BillingError(code, fieldErrors?)` โดย `invalid_input` พก `fieldErrors` (ช่อง → คีย์ `billing.errors.*`); อื่นๆ ไม่ผูกช่อง
