# Mock Auth & Role Guard Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** หน้า login/สมัคร (ผู้เช่า), ออกจากระบบ และ route guard ตาม role โดยข้อมูลจำลองในเบราว์เซอร์ แทนที่ `RoleSwitcher` ชั่วคราว

**Architecture:** interface `AuthApi` แบบ async + `localAuthApi` (localStorage) → `AuthProvider`/`useAuth()` → guard ที่ครอบ route ของ role หน้าจอไม่แตะ localStorage โดยตรง เมื่อมีหลังบ้านเปลี่ยนแค่ตัวสร้าง `AuthApi`

**Tech Stack:** เดิม (React 19, Vite, TS, Tailwind v4, react-router, react-i18next, Vitest + RTL + user-event) ไม่เพิ่มแพ็กเกจ

**Spec:** `docs/superpowers/specs/2026-11-08-mock-auth-design.md`
**Requirement:** PDF ITDS262 FR1 (ผู้เช่าสร้างบัญชี), FR2 (ผู้เช่า/นิติบุคคล/ช่างเข้าสู่ระบบ)

## Global Constraints

- ไม่มีหลังบ้าน ไม่มีแพ็กเกจใหม่ ห้ามเรียกเครือข่าย
- localStorage คีย์ `condo:users` (รายการบัญชี) และ `condo:session` (id ผู้ใช้ปัจจุบัน) เท่านั้น
- รหัสผ่านเก็บเป็น hash SHA-256 (hex) ห้ามเก็บ plain text; เซสชันเก็บแค่ id
- สมัครได้เฉพาะ role `tenant`; บัญชีทดลอง seed 3 บัญชี: `tenant01` (tenant), `staff01` (juristic), `tech01` (technician) รหัสผ่านเดียวกัน `demo1234`
- กฎสมัคร: username 4–20 ตัว `[a-z0-9_]` (trim แล้วเทียบแบบไม่สนตัวพิมพ์ ไม่ซ้ำ); password ≥ 8 ตัวและต้องตรงกับช่องยืนยัน; ชื่อ-นามสกุลไม่ว่าง; email รูปแบบถูกต้อง; เบอร์โทร 10 หลักขึ้นต้น `0`
- login ผิดทุกกรณีแสดงข้อความเดียว: `ชื่อผู้ใช้หรือรหัสผ่านไม่ถูกต้อง` (en: `Invalid username or password`)
- ข้อความ UI ทั้งหมดมาจากไฟล์ i18n ครบทั้ง th และ en (เทสคีย์ที่มีอยู่แล้วจะ fail ถ้าขาด)
- ข้อมูลใน localStorage เสียหาย/เขียนไม่ได้/อ่านไม่ได้ ต้องไม่ทำให้แอปพัง (ทำงานในหน่วยความจำต่อ)
- Route: `/login`, `/register` เป็นหน้าเดี่ยว ไม่ใช้ AppShell; `/tenant/*`, `/juristic/*`, `/technician/*` ต้องล็อกอินและ role ตรง prefix; ผู้ใช้ที่ role ไม่ตรงถูกพา (replace) ไปหน้าแรกของ role ตัวเอง; ล็อกอินแล้วเข้า `/login`/`/register` ถูกพาไปหน้าแรกของ role
- ข้อจำกัดเดิมยังใช้: ไม่มี CDN, ฟอนต์ self-host, tokens จาก `@theme`, `tabular-nums` สำหรับตัวเลข, breakpoints เดิม

## Review Focus

- `condo:users` / `condo:session` เป็น JSON เสีย, รูปร่างผิด, หรือ session ชี้ผู้ใช้ที่ไม่มี ต้องไม่พังและ seed/ล้างให้ถูก (Task 2)
- localStorage throw ตอนอ่านหรือเขียน สมัคร/ล็อกอินต้องยังทำงานในหน่วยความจำ (Task 2)
- username มีช่องว่างหน้า-หลังหรือตัวพิมพ์ใหญ่ (`" Tenant01 "`) ต้อง login ได้และสมัครซ้ำไม่ได้ (Task 1, 2)
- กดส่งฟอร์มซ้ำระหว่างรอ ต้องไม่สมัครซ้ำ/ไม่ยิงสองครั้ง ปุ่มต้อง disabled ระหว่างรอ และหลังผิดช่องรหัสผ่านต้องถูกล้าง (Task 4)
- กด Back หลังออกจากระบบต้องไม่เห็นหน้าที่ต้องล็อกอิน และ deep link `/juristic/billing` ตอนยังไม่ล็อกอินต้องไป `/login` (Task 5, 6)
