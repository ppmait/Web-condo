# Meters, Invoices & Payments — Design Spec

วันที่: 2026-11-08
ต่อยอดจาก: `2026-11-08-units-leases-design.md`, `2026-11-08-mock-auth-design.md`
Requirement: PDF ITDS262 — FR11 (บันทึกมิเตอร์น้ำ-ไฟรายเดือน), FR12 (คำนวณค่าน้ำ ค่าไฟ ค่าส่วนกลาง ออกใบแจ้งหนี้อัตโนมัติ), FR13 (แจ้งเตือนใบแจ้งหนี้ถึงผู้เช่า), FR14 (ผู้เช่าตรวจใบแจ้งหนี้), FR15 (ผู้เช่าชำระ: สแกน QR + แนบสลิป), FR16 (นิติบุคคลตรวจการชำระเงิน), FR17 (นิติบุคคลออกใบเสร็จ)
แบบอ้างอิงหน้าตา: `billing_utility` และส่วน "ใบแจ้งหนี้ & ชำระเงิน" ของ `resident_web_portal_1204_2` ใน zip Stitch (ขอบเขต A: เฉพาะส่วนที่ตรง FR)

## 1. เป้าหมาย

นิติบุคคลจดมิเตอร์ ออกใบแจ้งหนี้รายเดือน ตรวจสลิป และออกใบเสร็จ ผู้เช่าเห็นใบแจ้งหนี้ของตัวเอง ชำระและส่งสลิป ได้รับแจ้งเตือน และดูใบเสร็จ โดยไม่มีหลังบ้าน (ข้อมูลจำลองใน localStorage)

เกณฑ์ความสำเร็จ:
- นิติบุคคลจดมิเตอร์ → ออกบิลทั้งรอบ → ได้ใบแจ้งหนี้ที่ยอดตรงกับ (หน่วยน้ำ × อัตรา) + (หน่วยไฟ × อัตรา) + (ขนาดห้อง × อัตราส่วนกลาง) และสร้างซ้ำสำหรับห้องเดิมในรอบเดิมไม่ได้
- ผู้เช่า `tenant01` เห็นใบแจ้งหนี้ ส่งสลิป → นิติบุคคลอนุมัติ → ออกใบเสร็จ → ผู้เช่าเห็นใบเสร็จและมีแจ้งเตือนครบทุกขั้น
- ผู้เช่าเห็นเฉพาะใบแจ้งหนี้ของตัวเอง; ช่างและบทบาทอื่นเข้าหน้าของนิติบุคคลไม่ได้
- เปิดครั้งแรกเห็นข้อมูลตัวอย่างหลายรอบ ข้อมูลอยู่หลังรีเฟรช `npm test` และ `npm run build` ผ่าน

## 2. ขอบเขต

**ทำ:** ฝั่งนิติบุคคล `/juristic/billing` (4 แท็บ: จดมิเตอร์ / ใบแจ้งหนี้ / ตรวจสลิป / อัตราค่าบริการ + การ์ดสรุป + เลือกรอบเดือน), ฝั่งผู้เช่า `/tenant/billing` (ใบแจ้งหนี้, QR, แนบสลิป, ประวัติ, ใบเสร็จ), กล่องแจ้งเตือนในแอป (ไอคอนกระดิ่งของผู้เช่า)

**ไม่ทำรอบนี้:** นำเข้า Excel/CSV, ประวัติรอบบิลแบบแยกหน้า, ตรวจจับยอดผิดปกติ, ใบกำกับภาษีย่อและ QR กรมสรรพากร, ชำระด้วยบัตร, แก้ไข/ยกเลิกใบแจ้งหนี้หลังออกแล้ว, ดูรูปสลิปจริง, push notification จริง (NFR5), ตรวจยอดสลิปอัตโนมัติ, ค่าปรับล่าช้า

## 3. การตัดสินใจ

| หัวข้อ | ตัดสินใจ |
|---|---|
| ที่เก็บข้อมูล | localStorage คีย์เดียว `condo:billing` = `{ version: 1, rates, readings, invoices, notifications }` ผ่าน interface `BillingApi` (async) + `localBillingApi`; `BillingProvider`/`useBilling()` |
| อ้างอิงข้ามโมดูล | ใบแจ้งหนี้/มิเตอร์อ้าง `unitId`/`leaseId` ของ `condo:property`; ตอนโหลด `localBillingApi` ตรวจกับข้อมูลห้อง/สัญญาปัจจุบัน ถ้าไม่ตรง (เช่น property ถูก seed ใหม่) → seed `condo:billing` ใหม่ทั้งก้อน ข้อมูลเสีย/ผิดรูป/ผิดกฎก็ seed ใหม่ (เหมือน property) และอ่านจาก storage ใหม่ทุกครั้งที่เรียก |
| รอบบิล | เดือนปฏิทิน `YYYY-MM`; "วันนี้" ฉีดได้ ใช้ชั้น `dates` เดิม |
| อัตรา | ค่าน้ำ ฿/หน่วย, ค่าไฟ ฿/หน่วย, ค่าส่วนกลาง ฿/ตร.ม. (ตั้งต้น 18 / 7 / 60) เป็นจำนวนเต็มบาท > 0; ใบแจ้งหนี้เก็บอัตราที่ใช้ตอนออกบิล (snapshot) แก้อัตราภายหลังไม่กระทบบิลเก่า |
| ใครถูกเรียกเก็บ | ห้องที่มีสัญญาไม่ถูกยกเลิก (หรือยกเลิกแต่ `cancelledAt` ≥ วันแรกของรอบ) ซึ่งช่วงสัญญาทับซ้อนกับเดือนนั้น; ห้องเจ้าของอยู่เอง/ว่าง/ปิดปรับปรุงไม่ถูกเรียกเก็บ |
| การปัดเศษ | ทุกบรรทัดค่าใช้จ่ายปัดเป็นบาทเต็ม (ปัดครึ่งขึ้น) แล้วค่อยรวมเป็นยอดสุทธิ |
| ผู้เช่ากับห้อง | ผู้เช่าเห็นใบแจ้งหนี้ที่ `tenantPhone` (snapshot ในบิล) ตรงกับเบอร์ในบัญชี; บัญชีทดลอง `tenant01` ปรับเบอร์ให้ตรงกับผู้เช่าของห้อง A-1204; ผู้ที่สมัครเองต้องใช้เบอร์ที่ตรงกับสัญญา ไม่งั้นเห็นข้อความ "ยังไม่มีใบแจ้งหนี้" |
| QR และสลิป | QR เป็นภาพตัวอย่างคงที่ (SVG ในโค้ด ติดป้าย "ตัวอย่าง") พร้อมยอดและเลขบิล; สลิปรับ JPG/PNG ≤ 5 MB เก็บเฉพาะชื่อ/ขนาด/ชนิดไฟล์ ไม่เก็บเนื้อไฟล์ |
| แจ้งเตือน (FR13) | กล่องแจ้งเตือนในแอปของผู้เช่า: ออกใบแจ้งหนี้, สลิปถูกปฏิเสธ, ออกใบเสร็จ; กดแล้วเปิดใบแจ้งหนี้นั้น และทำเครื่องหมายอ่านแล้ว |
| การออกใบเสร็จ | แยกจากการอนุมัติ: อนุมัติสลิป → "ชำระแล้ว" ; นิติบุคคลกด "ออกใบเสร็จ" → เลขที่ใบเสร็จ + แจ้งเตือนผู้เช่า |

## 4. ข้อมูลและกฎ

**MeterReading:** `id, unitId, period, waterPrev, waterCurr, electricPrev, electricCurr` — จำนวนเต็ม ≥ 0, `Curr ≥ Prev`, หนึ่งรายการต่อห้องต่อรอบ
- ค่าก่อนหน้า (`Prev`) ตั้งต้นจากค่าปัจจุบันของรอบก่อนหน้าของห้องเดียวกัน; ถ้าไม่เคยมีรอบก่อน กรอกค่าก่อนหน้าเองได้ (ค่าอ้างอิงเริ่มต้น)
- แก้ไขได้จนกว่าจะออกใบแจ้งหนี้ของห้องและรอบนั้น หลังออกบิลล็อก
- แก้ค่าปัจจุบันของรอบหนึ่งที่มีรอบถัดไปอยู่แล้ว ห้ามทำให้ค่าก่อนหน้าของรอบถัดไปไม่สอดคล้อง (รอบถัดไปต้อง `Prev ≥` ค่าปัจจุบันใหม่ หรือบังคับให้แก้รอบนั้นด้วย)

**Invoice:** `id, number, period, unitId, leaseId, tenantName, tenantPhone, water{units,rate,amount}, electric{units,rate,amount}, common{areaSqm,rate,amount}, total, issuedAt, dueDate, payments[], receipt?`
- `number` = `INV-<YYYYMM>-<รหัสห้องไม่มีขีด>` ไม่ซ้ำ; `dueDate` = วันที่ 5 ของเดือนถัดไป
- ออกบิลทั้งรอบ: สร้างใบแจ้งหนี้ให้ห้องที่ถูกเรียกเก็บและมีมิเตอร์ครบ และยังไม่มีบิลของรอบนั้น; ห้องที่ยังไม่มีมิเตอร์ถูกข้ามและแสดงรายชื่อ; กดซ้ำไม่สร้างซ้ำ; แจ้งเตือนผู้เช่าทุกใบที่ออก
- **สถานะที่แสดง (คำนวณ):** paid (มีสลิปที่อนุมัติ) > verifying (มีสลิปรอตรวจ) > overdue (ยังไม่ชำระและ `dueDate` < วันนี้) > unpaid; ใบที่ paid แล้วไม่มีเลขใบเสร็จ = "รอออกใบเสร็จ"

**Payment (สลิป):** `id, submittedAt, fileName, fileSize, status (pending | approved | rejected), reviewedAt?, rejectReason?`
- ส่งสลิปได้เมื่อบิลยังไม่ paid และไม่มีสลิปรอตรวจ; ไฟล์ผิดชนิด/ใหญ่เกิน/ไม่ได้แนบ → ข้อความ "กรุณาแนบไฟล์สลิปการโอนเงินให้ถูกต้อง"
- นิติบุคคลตรวจรายการที่ pending: อนุมัติ หรือปฏิเสธ (ต้องระบุเหตุผล) ตรวจแล้วเปลี่ยนไม่ได้; ปฏิเสธแล้วผู้เช่าส่งสลิปใหม่ได้

**Receipt:** `number` = `RC-<YYYYMM>-<รหัสห้อง>`, `issuedAt`, `amount` ออกได้เมื่อ paid และยังไม่เคยออก ออกได้ครั้งเดียว

ข้อผิดพลาดของชั้นข้อมูล: `BillingError` พร้อม code `invalid_input` (พก `fieldErrors` ช่อง → คีย์ข้อความ), `invoice_exists`, `not_found`, `slip_pending`, `already_paid`, `already_reviewed`, `receipt_exists`, `not_payable`

## 5. หน้าจอ

- **นิติบุคคล `/juristic/billing`:** ตัวเลือกรอบเดือน + การ์ดสรุป (ยอดเรียกเก็บรอบนี้, ชำระแล้ว, ค้างชำระ, สลิปรอตรวจ, ห้องรอจดมิเตอร์)
  - *จดมิเตอร์:* ตารางห้องที่ถูกเรียกเก็บในรอบ (ค่าก่อนหน้า, ช่องกรอกค่าปัจจุบัน, หน่วยที่ใช้, เงินที่คำนวณ, สถานะ ยังไม่จด/จดแล้ว/ออกบิลแล้ว) และปุ่ม "ออกใบแจ้งหนี้รอบนี้"
  - *ใบแจ้งหนี้:* ตาราง (เลขที่, ห้อง, ผู้เช่า, ยอด, กำหนดชำระ, สถานะ) กรองสถานะ รายละเอียดแยกค่าน้ำ/ไฟ/ส่วนกลาง และปุ่ม "ออกใบเสร็จ"
  - *ตรวจสลิป:* คิวสลิปรอตรวจ (บิล, ห้อง, ชื่อไฟล์, วันที่ส่ง, ยอด) ปุ่ม อนุมัติ / ปฏิเสธ (กล่องเหตุผล)
  - *อัตราค่าบริการ:* ฟอร์มแก้ 3 อัตรา
- **ผู้เช่า `/tenant/billing`:** การ์ด "ต้องชำระ" (บิลที่ยังไม่ paid), ตารางประวัติ, รายละเอียดบิลในกล่องโต้ตอบ: แยกบรรทัดค่าใช้จ่าย, QR ตัวอย่าง, ช่องแนบสลิป, สถานะ/เหตุผลที่ถูกปฏิเสธ, ปุ่ม "ดูใบเสร็จ" เมื่อออกแล้ว
- **กระดิ่งแจ้งเตือน (ผู้เช่า):** ใน header แสดงจำนวนที่ยังไม่อ่าน เปิดรายการแล้วกดไปที่บิล
- ฟอร์มใน `Modal` ด้วย `FormField`, กดซ้ำระหว่างรอไม่ได้, โฟกัสช่องแรกที่ผิด, ลบ/อนุมัติ/ปฏิเสธมีการยืนยันตามความเหมาะสม; ตัวเลขเงินชิดขวา `tabular-nums`; ตารางเลื่อนข้างในกรอบของตัวเอง; ข้อความ th/en ครบ

## 6. การทดสอบ

- `billing/rules.ts` (ฟังก์ชันล้วน, ใหญ่ที่สุด): คำนวณรายบรรทัดและปัดเศษ (ขอบ .5), ห้องที่ถูกเรียกเก็บ (สัญญาครอบรอบบางส่วน, ยกเลิกก่อน/หลังรอบ, ว่าง/เจ้าของอยู่เอง/ปิด), ค่าก่อนหน้าตั้งต้น, `Curr < Prev`, สถานะที่แสดงทุกกรณีและขอบ `dueDate` = วันนี้, ตรวจสลิป (ชนิด/ขนาดไฟล์ขอบ 5 MB), การออกบิลซ้ำ
- `localBillingApi`: ออกบิลทั้งรอบ (ข้ามห้องที่ไม่มีมิเตอร์, ไม่สร้างซ้ำ, เก็บอัตรา snapshot), ส่งสลิป/อนุมัติ/ปฏิเสธ/ออกใบเสร็จ ครบ code ของข้อผิดพลาด, แจ้งเตือนถูกต้องคน, อ่านจาก storage ใหม่ทุกครั้ง (สองอินสแตนซ์), ข้อมูลเสีย/อ้างอิงห้องที่ไม่มี/ไม่สอดคล้องแล้ว seed ใหม่, storage อ่าน/เขียนไม่ได้, ล้มเหลวชั่วคราวไม่ถูกแคช
- หน้าจอทั้งสองฝั่ง: ขั้นตอนครบวงจรด้วย api จำลอง, ฟอร์มผิดแล้วโฟกัส, กดซ้ำเรียก api ครั้งเดียว, ผู้เช่าเห็นเฉพาะบิลตัวเอง, เบอร์ไม่ตรงเห็นข้อความว่าง, สลิปผิดชนิด/ใหญ่เกิน, กระดิ่งแจ้งเตือน, ช่างและผู้เช่าเข้าหน้านิติไม่ได้, สลับภาษา
- ตรวจจริงในเบราว์เซอร์ที่ 1280/390/320px และจอเตี้ย

## 7. ความเสี่ยง

- ผูกกับ `condo:property` ผ่านรหัสห้อง/สัญญา: ข้อมูลสองก้อนอาจไม่ตรงกัน จึงต้องตรวจอ้างอิงและ seed ใหม่ (ข้อ 3) และข้อมูลตัวอย่างต้องสร้างจาก seed ของห้อง/สัญญาด้วยวันที่สัมพัทธ์กับ "วันนี้"
- บัญชีทดลองที่ seed ไว้ในเบราว์เซอร์เดิมมีเบอร์เก่า ผู้ใช้เดิมต้องล้าง `condo:users` (หรือเปิดโปรไฟล์ใหม่) จึงจะเห็นบิลของ `tenant01`
- ไม่มีการแก้/ยกเลิกใบแจ้งหนี้หลังออก: ใส่ผิดต้องแก้ภายนอกระบบ เป็นข้อจำกัดที่ยอมรับในรอบนี้
- เสียค่าส่วนกลางตามขนาดห้องเท่านั้น (ไม่รวมกรณีสัญญาเริ่มกลางเดือน: คิดเต็มเดือน)
- ไม่เก็บรูปสลิป: นิติบุคคลตรวจจากชื่อไฟล์เท่านั้น (ตัวจำลอง ไม่ใช่การตรวจจริง) และไม่ตรง NFR1/NFR8 ในเชิงความปลอดภัย
