# Announcements — Design Spec

วันที่: 2026-11-10
Requirement: PDF ITDS262 — FR26 (นิติบุคคลสร้างประกาศข่าวสารภายในอาคาร), FR27 (ผู้เช่าดูประกาศข่าวสารภายในอาคาร) (ไม่มี use case บรรยายเพิ่ม)
แบบอ้างอิงหน้าตา: `announcement_notification_hub` และ `announcements_documents_hub` ใน zip Stitch (เฉพาะส่วนประกาศ ไม่ทำเอกสารแนบ)
ต่อจาก: `2026-11-09-facilities-parcels-design.md` (รูปแบบเดียวกัน: กฎล้วน → api จำลองใน localStorage → Provider → หน้าจอ)

## 1. เป้าหมาย

นิติบุคคลสร้าง แก้ไข และลบประกาศ ผู้เช่าเห็นประกาศที่ยังเผยแพร่ อ่านได้ มีป้ายสำหรับที่ยังไม่อ่าน และได้แจ้งเตือนในกระดิ่งรวม ทั้งหมดเป็นข้อมูลจำลองในเบราว์เซอร์ (ไม่มีหลังบ้าน) และสลับเป็นหลังบ้านจริงได้โดยเขียน `AnnouncementsApi` ตัวใหม่

## 2. ขอบเขต

- **นิติบุคคล** `/juristic/announcements`: รายการประกาศทั้งหมด (ปักหมุดก่อน แล้วใหม่ไปเก่า), ตัวกรอง กำลังเผยแพร่ / หมดอายุแล้ว / ทั้งหมด, ปุ่ม "สร้างประกาศ", แถวละปุ่ม แก้ไข และ ลบ (ลบผ่านกล่องยืนยัน), จำนวนผู้ที่อ่านแล้วของแต่ละประกาศ (FR26)
- **ผู้เช่า** `/tenant/announcements`: การ์ดของประกาศที่ยังเผยแพร่ (ปักหมุดก่อน แล้วใหม่ไปเก่า) ป้ายหมวด วันที่ ตัวอย่างเนื้อหา และป้าย "ใหม่" เมื่อยังไม่อ่าน; เปิดอ่านแล้วถือว่าอ่านแล้ว (FR27)
- **กระดิ่งรวม** เพิ่มแหล่งที่สี่ (hook `useNotifications` เดิม): ผู้เช่าได้ "ประกาศใหม่: {{หัวข้อ}}" ต่อประกาศที่ยังเผยแพร่และยังไม่อ่าน

**ไม่ทำรอบนี้:** เอกสารแนบ, เลือกกลุ่มผู้รับ, ตั้งเวลาเผยแพร่ล่วงหน้า, ความคิดเห็น/ตอบกลับ, แจ้งเตือนเมื่อใกล้หมดอายุ, รายชื่อผู้ที่ยังไม่อ่านรายห้อง (มีแค่จำนวนที่อ่านแล้ว), push จริง (NFR5)

## 3. การตัดสินใจ

| เรื่อง | ตัดสินใจ |
|---|---|
| หมวด | `general` (ทั่วไป), `maintenance` (งดน้ำ-ไฟ/ซ่อมบำรุง), `event` (กิจกรรม), `urgent` (เร่งด่วน); ป้าย: urgent = critical, maintenance = pending, event = settled, general = inactive; ข้อความหมวดแสดงเสมอ (ไม่พึ่งสีอย่างเดียว) |
| ฟิลด์ | `title` 1–100 ตัวอักษรหลัง trim; `body` 1–2000 หลัง trim; `category`; `pinned` boolean; `expiresOn?` (YYYY-MM-DD, ไม่บังคับ) |
| หมดอายุ | **คำนวณ ไม่เก็บ:** หมดอายุเมื่อ `expiresOn < วันนี้` (วันหมดอายุพอดียังเผยแพร่อยู่); วันหมดอายุตอนสร้าง/แก้ต้องเป็นวันที่จริงและ `≥ วันนี้` (เก่ากว่านี้ผิด); แก้ประกาศที่หมดอายุแล้วให้ขยายวันหมดอายุได้ (วันใหม่ต้อง `≥ วันนี้`) |
| ลำดับแสดง | ปักหมุดก่อน แล้ว `createdAt` ใหม่ไปเก่า แล้วรหัสมากไปน้อย; ผู้เช่าเห็นเฉพาะที่ยังเผยแพร่ นิติบุคคลเห็นทั้งหมด (กรองได้) |
| การอ่าน | `readBy: string[]` = เบอร์โทรของผู้เช่าที่อ่านแล้ว (ไม่ซ้ำ); เปิดรายละเอียด → `markRead(announcementId, phone)` ครั้งเดียว (เรียกซ้ำไม่เปลี่ยนอะไร); เป็นการเขียนมูลค่าต่ำ ใช้หน่วยความจำสำรองได้ |
| แก้ไข | แก้หัวข้อหรือเนื้อหา → `readBy` ถูกล้าง (ผู้เช่าเห็น "ใหม่" อีกครั้ง); แก้เฉพาะหมวด ปักหมุด หรือวันหมดอายุ ไม่ล้าง; บันทึก `updatedAt`; การแก้ที่ไม่มีอะไรเปลี่ยนไม่เขียนอะไร |
| ลบ | ลบถาวร (ไม่มีถังขยะ); กล่องที่เปิดค้างอยู่ของประกาศที่ถูกลบ → ข้อความ "ไม่พบประกาศนี้แล้ว" และโหลดใหม่ |
| แจ้งเตือน | ไม่เก็บเป็นระเบียนแยก คำนวณจากประกาศ: ผู้เช่าได้หนึ่งรายการต่อประกาศที่ยังเผยแพร่และเบอร์ของตนไม่อยู่ใน `readBy`; กดแล้วไป `/tenant/announcements?announcement=<id>` และทำเครื่องหมายอ่าน; "อ่านทั้งหมด" = อ่านทุกประกาศที่ยังเผยแพร่; นิติบุคคลและช่างไม่ได้แจ้งเตือนจากแหล่งนี้ |
| ลิงก์ | `?announcement=<id>` ที่ไม่มี/หมดอายุแล้ว (ฝั่งผู้เช่า) → เพิกเฉยและล้างพารามิเตอร์ |
| รหัส | `AN-0001`… = ค่ามากสุดที่มี + 1 |
| ผู้เขียน | `authorName` = ชื่อบัญชีนิติบุคคลที่สร้าง (snapshot) |
| ข้อมูลหาย/เสีย | คีย์ `condo:announcements` = `{ version: 1, announcements }`; seed ใหม่เมื่อว่าง/เสีย/ผิดกฎ (รหัสซ้ำ, วันที่ไม่จริง, `updatedAt < createdAt`, `readBy` ซ้ำ, หมวดผิด); **อ่านจากที่เก็บเสมอเมื่อข้อมูลในที่เก็บใช้ได้** แม้แท็บนี้เคยบันทึกไม่สำเร็จ; วันที่ `updatedAt` ไม่ย้อนหลังกว่า `createdAt`/`updatedAt` เดิมแม้นาฬิกาเครื่องถอย; การเขียนที่คนพึ่งพา (สร้าง แก้ ลบ) ทำบนสำเนาและเขียนแบบเคร่งครัด → `storage_failed` และไม่เปลี่ยนอะไร |
| ข้อมูลตัวอย่าง | 5 รายการอิงจากวันนี้: ปักหมุด 1 (กฎอาคาร/ที่จอดรถ), เร่งด่วน 1 (งดน้ำ พรุ่งนี้), กิจกรรม 1, ทั่วไป 1, หมดอายุแล้ว 1; ผู้เช่า demo `0810000001` อ่านแล้วบางรายการ และมีอย่างน้อย 2 รายการที่ยังไม่อ่าน |

## 4. ข้อมูลและกฎ

- `Announcement`: `id`, `code`, `title`, `body`, `category`, `pinned`, `expiresOn?`, `createdAt`, `updatedAt`, `authorName`, `readBy: string[]`
- `AnnouncementInput`: `title`, `body`, `category`, `pinned`, `expiresOn` (สตริงว่าง = ไม่มี)
- กฎล้วน (`rules.ts`): `validateAnnouncement(input, today)`, `isExpired(announcement, today)`, `isLive(announcement, today)`, `sortAnnouncements(list)`, `isUnreadBy(announcement, phone, today)`, `contentChanged(before, input)`, `nextCode(items)`, `categoryBadge(category)`, `preview(body, max)` (ตัดที่ 120 ตัวอักษรต่อด้วย `…`)
- ข้อผิดพลาด: `invalid_input` (พร้อมคีย์รายช่อง), `not_found`, `storage_failed`
- `AnnouncementsApi`: `load`, `create(input, authorName)`, `update(id, input)`, `remove(id)`, `markRead(id, phone)`, `markAllRead(phone)`; การเขียนสามอย่างแรกทำบนสำเนาและเขียนแบบเคร่งครัด อ่านใหม่ก่อนเขียนทุกครั้งโดยไม่มี `await` คั่น

## 5. หน้าจอ

- **ผู้เช่า:** การ์ดประกาศ (ป้ายหมวด, ปักหมุดมีไอคอนพร้อมข้อความ "ปักหมุด", หัวข้อ, วันที่, ตัวอย่าง, ป้าย "ใหม่"); กดเปิดรายละเอียด (หมวด, วันที่ประกาศ, วันหมดอายุถ้ามี, ผู้ประกาศ, เนื้อหาเต็มเว้นบรรทัดตามที่พิมพ์); ข้อความว่างเมื่อไม่มีประกาศ; อ่าน `?announcement=`
- **นิติบุคคล:** ตัวกรอง + ตาราง (รหัส, หมวด, หัวข้อ, วันที่, หมดอายุ, ปักหมุด, อ่านแล้ว, สถานะ กำลังเผยแพร่/หมดอายุ, ปุ่ม แก้ไข/ลบ); ฟอร์มสร้าง/แก้ไขใน Modal (ตรวจก่อนส่ง โฟกัสช่องแรกที่ผิด กันกดซ้ำ ข้อความ `storage_failed`); ลบผ่านกล่องยืนยัน (ไม่ซ้อนกล่องอื่น เพราะแก้/ลบทำจากแถวในตารางโดยตรง)
- **กระดิ่ง:** ข้อความใหม่ผ่าน i18n ปลายทางผู้เช่า; ใช้ hook รวมเดิม
- ข้อความทั้งหมดผ่าน i18n (th/en); ตารางในกล่องเลื่อนข้างที่ `relative`; ป้ายสถานะมีข้อความเสมอ; ไม่ล้นจอที่ 320px; Modal ใช้งานได้ที่จอเตี้ย; รหัสไม่ตัดบรรทัด; key ของกล่องที่ซ้อนกันต้องไม่ซ้ำกัน

## 6. การทดสอบ

กฎล้วนทุกกรณีขอบ (หมดอายุพอดี/เมื่อวาน, หัวข้อ 100/101, เนื้อหา 2000/2001, วันหมดอายุไม่จริง/ก่อนวันนี้, ลำดับการแสดงเมื่อปักหมุดและวันที่เท่ากัน, ตัวอย่างที่ตัดกลางตัวอักษรไทย, การเปลี่ยนเนื้อหาเทียบการเปลี่ยนเฉพาะปักหมุด); api: สร้าง/แก้/ลบ/อ่าน, แก้แล้วล้างการอ่านเฉพาะเมื่อหัวข้อหรือเนื้อหาเปลี่ยน, แก้ไม่เปลี่ยนอะไรไม่เขียน, ลบแล้วหาย, สองแท็บสร้างพร้อมกันได้รหัสไม่ซ้ำ, ทุกการเขียนที่เคร่งครัดเมื่อพื้นที่เต็ม/เขียนไม่ได้ → `storage_failed` และข้อมูลเดิมครบ, **แท็บที่เคยบันทึกไม่สำเร็จเห็นสิ่งที่แท็บอื่นบันทึกทีหลัง**, **นาฬิกาถอยหลังแล้วข้อมูลไม่ถูกแทนที่**, ข้อมูลเสียแต่ละแบบ → seed, `markRead` ซ้ำไม่เปลี่ยนอะไร; UI: ผู้เช่าไม่เห็นประกาศที่หมดอายุ, ป้าย "ใหม่" หายหลังอ่าน, ตัวอย่างและเนื้อหาเต็มถูกต้อง, ฟอร์มไม่ครบเรียก api ไม่ได้ + โฟกัส, กดซ้ำเรียกครั้งเดียว, แก้/ลบตามกฎ, ลบแล้วกล่องที่เปิดค้างขึ้นข้อความ, `?announcement=` ของที่ไม่มี/หมดอายุเพิกเฉย; กระดิ่งรวมสี่ที่มานับถูก (ประกาศที่ยังไม่อ่านของผู้เช่าเท่านั้น), กดแล้วทำเครื่องหมายอ่านและเปิดประกาศ, นิติบุคคล/ช่างไม่ได้แจ้งเตือนประกาศ; ตรวจบนเบราว์เซอร์จริงที่ 1280/390/320px และจอเตี้ย 480px โดยนับ console error ทุกข้อความเป็นความล้มเหลว

## 7. ความเสี่ยง

- ตัวตนผู้อ่านคือเบอร์โทร (รับสืบมาจากโมดูลก่อนหน้า): บัญชีเบอร์เดียวกันนับเป็นผู้อ่านคนเดียว และใครสมัครด้วยเบอร์คนอื่นจะ "อ่านแทน" ได้
- จำนวน "อ่านแล้ว" นับเบอร์โทร ไม่ใช่จำนวนห้อง และไม่รู้จำนวนผู้เช่าทั้งหมด จึงไม่มีเปอร์เซ็นต์
- สิทธิ์เป็นฝั่งไคลเอนต์เท่านั้น (ตัวจำลอง) หลังบ้านจริงต้องตรวจซ้ำและกรองประกาศหมดอายุฝั่งเซิร์ฟเวอร์
- เนื้อหาประกาศเป็นข้อความธรรมดา (แสดงเป็นข้อความ ไม่ตีความ HTML) ไม่มีรูป/ลิงก์ที่กดได้
